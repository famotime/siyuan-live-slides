## 一、背景与痛点分析

在演讲、技术分享、教学或产品汇报等演示（Presentation）场景下，**视觉连贯性与心流体验（Immersion）**至关重要。目前传统演示工具（如 PowerPoint / Keynote）以及主流 Markdown 幻灯片方案（如原生 Slidev、Marp）在处理超链接跳转时存在严重的体验撕裂：

1. **外部 Web 链接的割裂感**：
   - 演示者点击幻灯片中的网页、文档或在线 Demo 链接时，系统被迫触发跨应用切换（切出到外部 Chrome/Edge）；
   - 全屏模式往往被系统强制退出或遮挡，杂乱的桌面图标、任务栏、甚至私人通知瞬间暴露在观众面前；
   - 演示完毕关闭浏览器后，演讲者需在任务栏中重新找回演示窗口，极易造成现场节奏中断甚至技术翻车。

2. **思源内部文档/块链接的跳转破坏**：
   - 在幻灯片中引用思源知识库文档或参考卡片时，常规点击会直接切换思源主界面的编辑标签页；
   - 演示者当前的放映全屏、未提交的排版视图或特定动画步进（`v-click` Step）容易被重置或覆盖，演讲进度丢失。

**核心目标**：构建一套**原位沉浸式扩展层（In-situ Immersion Overlay）**，实现：
- 点击 Web 链接：在放映界面**前台以微型浏览器即时呈现**，关闭后立即原地返回原播放页，支持多级视口与缩放；
- 点击思源笔记链接：在放映界面**原地拉起原生 Protyle 速览抽屉**，支持查看甚至即时勘误，不退出演示全屏、不切换工作区标签页。

## 二、总体架构与交互形态设计

系统采用 **“演示全屏包裹层 + 双轨沉浸式浮层（Slide-over Drawer / Modal View）”** 架构，视口逻辑模型如下：

```
┌────────────────────────────────────────────────────────────────────────┐
│  全屏放映总容器 (.spm-slides-fullscreen-container)                     │
│                                                                        │
│  ┌─────────────────────────┐  ┌──────────────────────────────────────┐ │
│  │                         │  │ 沉浸式浮层抽屉 (Slide-over Drawer)   │ │
│  │                         │  ├──────────────────────────────────────┤ │
│  │                         │  │ [地址/标题] [➖ 100% ➕] [🗖最大化] [✕] │ │
│  │   当前 Slide 演示背景   │  ├──────────────────────────────────────┤ │
│  │                         │  │                                      │ │
│  │  • 原位冻结保留上下文   │  │  轨 A (Web 链接):                     │ │
│  │  • 页码与动画步进不丢失 │  │    Electron <webview> 微型浏览器      │ │
│  │                         │  │                                      │ │
│  │                         │  │  轨 B (思源链接):                     │ │
│  │                         │  │    思源原生 Protyle 速览/编辑引擎     │ │
│  │                         │  │                                      │ │
│  └─────────────────────────┘  └──────────────────────────────────────┘ │
│                                                                        │
│  ✦ 交互核心：按 ESC / 点击暗色遮罩 / 点击右上角 ✕ → 抽屉即刻平滑收起   │
│  ✦ 零切换窗口、零任务栏暴露、全屏状态完全不受干扰                      │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、场景 A：Web 外部链接（内置微型浏览器）详细方案

### 1. 屏幕空间利用机制（双模视口）
为了平衡“对照讲解”与“全屏深度展示”两种演讲诉求，内置浏览器提供两种视口形态：

* **形态 ①：侧滑对照抽屉（默认，占屏宽 60% ~ 75%）**：
  - 适合快速查阅参考资料、API 文档或佐证材料；
  - 左侧保持露出当前幻灯片的关键论点，观众可将 PPT 内容与网页事实进行对比。
* **形态 ②：全屏沉浸最大化（占屏宽 100%，占满 16:9 视口）**：
  - 适合现场演示可交互在线 Demo、产品官网或系统操作；
  - 抽屉顶部保留极窄半透明悬浮条（包含网址信息、缩放与还原按钮），视觉体验与原生全屏浏览器无异。

### 2. 页面缩放与缩放控制
基于 Chromium / Electron 底层能力，内置浏览器具备原生级缩放支持：
* **快捷手势与键鼠**：
  - 支持键盘标准快捷键：`Ctrl / Cmd + +`（放大）、`Ctrl / Cmd + -`（缩小）、`Ctrl / Cmd + 0`（重置 100%）；
  - 支持鼠标滚轮组合键：`Ctrl + 滚轮`；
  - 支持高精度触控板双指捏合缩放（Pinch-to-zoom）。
* **顶栏显式控制条**：
  - 提供 `[➖] 100% [➕]` 点击步进微调按钮，调用底层 `webview.setZoomFactor(factor)`，便于演讲者在投影大屏上单手鼠标点击放大关键代码或细节图。

### 3. 安全策略与 `X-Frame-Options` 破局机制
针对主流网站配置 `X-Frame-Options: SAMEORIGIN/DENY` 导致普通 `<iframe>` 白屏拦截的问题：
* **桌面端（Electron 环境，占 90%+ 场景）**：
  - 核心采用 Electron 原生 `<webview>` 标签；
  - `<webview>` 运行在独立的 Chromium 隔离上下文，不受宿主页面的 CSP / X-Frame-Options 限制，能完整加载各类现代 SPA 应用与登录态 Cookie。
* **兜底与降级保障（Fail-safe Fallback）**：
  - 浮层右上角常驻 `在外部浏览器打开 ↗` 快捷按钮；
  - Web 端（浏览器访问思源）环境若检测到 Frame 拒绝，展示友好占位卡片并提供一键外跳入口。

## 四、场景 B：思源笔记内部链接（Protyle 沉浸抽屉）详细方案

### 1. 能完整支持的核心能力（编辑器原生生态）
通过在抽屉容器中直接挂载思源官方编辑器实例：
```ts
new Protyle(plugin.app, containerEl, {
  blockId: targetBlockId,
  action: ['cb-get-hl', 'cb-get-context']
})
```
* **富文本与排版特性**：100% 支持所有原生块级渲染（代码高亮、数学公式、Mermaid 流程图、多维图表等）；
* **数据库属性视图（AV / Database）**：完全支持表格/看板/画廊的多维视图切换、行内单元格编辑、筛选与排序；
* **即时交互与微调编辑**：支持选中文本悬浮工具条、`/` 斜杠快捷输入、块菜单触发与现场内容勘误；数据修改后实时持久化至思源本地数据库。

### 2. 全局侧面板（Dock）与插件的边界及解决方案

| 类别 | 能否塞入抽屉 | 原因剖析 | 推荐应对与最佳实践 |
| :--- | :---: | :--- | :--- |
| **内联/编辑器级插件** | **支持** | 依附于 Protyle DOM 树与块级事件，随编辑器一并加载 | 直接可用，无需额外适配。 |
| **思源全局侧面板 (Dock)** | **受限** | 侧面板属于思源顶层布局管理器（`Layout/DockModel`），强塞会导致抽屉内嵌套多层侧边栏，破坏演示界面简洁度 | **方案 ①（推荐）：** 抽屉内置轻量大纲与属性卡片，覆盖 90% 查阅需求；<br>**方案 ②（深度操作）：** 右上角提供 `在独立窗口中打开 ↗`。 |

> **置顶独立小窗口机制**：
> 针对需要完整侧面板和多个重度 Dock 插件的场景，点击右上角调用思源 `openWindow({ doc: { id: targetId }, alwaysOnTop: true })`。
> 该独立窗口漂浮在演示全屏之上，具备全套侧边栏与插件环境；操作完毕后按 `Ctrl+W` 关闭，焦点平滑交还放映界面。

## 五、关键技术风险与防御机制

### 1. 全屏上下文层级与挂载点治理
* **风险**：若调用沙箱 `iframe.requestFullscreen()`，外部宿主挂载的抽屉将被遮盖在全屏图层之外。
* **规避方案**：将全屏作用域上提至外层包装器组件（`.spm-slides-fullscreen-container`），确保沙箱主播放区与上层抽屉处于同一个 Fullscreen 渲染树中。

### 2. 键盘事件与幻灯片翻页冲突
* **风险**：演讲者在微型浏览器中滚屏按 `Space`、在 Protyle 编辑器中输入文字时，事件冒泡触发 Slidev 全局翻页。
* **规避方案**：
  - 抽屉挂载激活时，向沙箱下发 `FREEZE_KEYBOARD_NAV` 指令；
  - 在抽屉根 DOM 节点拦截所有键盘事件并调用 `stopPropagation()`；
  - 建立 **双层 ESC 响应栈**：
    - 当前存在激活抽屉时：按下 `ESC` → **优先关闭并销毁抽屉**，不退出全屏；
    - 当前无抽屉时：按下 `ESC` → 恢复默认行为（退出全屏放映）。

### 3. 内存管理与生命周期销毁
* **风险**：演示过程中反复打开不同的外部复杂网页或超大思源长文档，DOM 节点与监听器若未释放将引发内存暴涨。
* **规避方案**：
  - Protyle 实例在抽屉关闭动画结束时，显式调用内部销毁管线并清空 DOM 容器；
  - `<webview>` 节点在抽屉隐藏时触发资源挂起，并在关闭时从 DOM 树彻底注销。

## 六、方案可行性综合评估表

| 评估维度 | Web 链接内置微型浏览器 | 思源内部链接 Protyle 抽屉 | 传统外跳浏览器/主界面切换 |
| :--- | :---: | :---: | :---: |
| **沉浸感与节奏保持** | ★★★★★ (原位呼出与收起) | ★★★★★ (零切页，保留现场) | ★★☆☆☆ (强行跳出，视觉割裂) |
| **技术实现可行性** | ★★★★☆ (桌面端依赖 webview) | ★★★★★ (原生 Protyle 现成可用) | ★★★★★ (已有机制) |
| **全屏稳定性** | 极高 (同级 DOM 树呈现) | 极高 (同级 DOM 树呈现) | 极差 (外部应用抢焦导致闪退) |
| **空间与缩放体验** | 70%~100% 双模，支持手势缩放 | 抽屉自适应，支持内容滚动 | 受制于外部操作系统窗口管理 |
| **研发复杂度** | 中等 | 中等 | 无额外研发 |

## 七、演进路线与实施规划

1. **第一阶段 (MVP)：思源内部链接 Protyle 原位抽屉**
   - 在幻灯片渲染层拦截 `siyuan://` 与块引用点击；
   - 封装 `ProtylePeekDrawer.vue` 组件，接入思源官方 `new Protyle` 引擎；
   - 实现双层 `ESC` 响应与遮罩点击收起，优先解决知识库回溯与即时勘误需求。

2. **第二阶段：Web 外部链接微型浏览器与视口双模切换**
   - 封装 `WebviewOverlayDrawer.vue` 组件，集成 Electron `<webview>`；
   - 实现 70% 宽 / 100% 满屏一键切换与 `setZoomFactor` 显式缩放控制；
   - 增加右上角“在系统浏览器中打开”与“置顶独立窗口打开”备选动作。

3. **第三阶段：全屏容器重构与事件总线协同**
   - 重构放映视图的全屏挂载点，统一全屏层级与 z-index 空间；
   - 完善全局快捷键阻断与平滑过渡动效。
