# 思源笔记设置面板排版与控件样式开发指南

> 本指南总结了在思源笔记（SiYuan）插件设置弹窗（`Setting` API）开发过程中，针对复杂设置项排版、内核样式副作用、原生控件适配（如开关与图标按钮）等关键技术难题的排查分析与实战规范。

---

## 1. 核心背景与常见坑点

在思源插件开发中，很多开发者会遇到设置页面显示异常，典型现象包括：
1. **左侧大面积留白，内容整体右偏**：调用 `setting.addItem` 后，设置项被强行挤在窗口右半边，左侧留出数百像素空白；
2. **开关控件拉伸变形与滑块错位**：原本精致的胶囊开关被横向拉伸变长，开启状态下滑块卡在中间（未滑到最右侧），在暗色主题下形似“异常污斑”或“黑块”；
3. **行间距过紧无分割线**：多个设置项挤压在一起，不同高度的项（有描述与无描述）视觉混乱；
4. **复合输入组件外突**：如密码输入框与“显示/隐藏”按钮横向堆叠，破坏了整齐统一的表单节奏。

## 2. 思源内核 Setting 布局机理深度解析

### 2.1 `direction: "row"` 的反直觉命名

思源内核中 `Setting.addItem(options)` 的 `direction` 参数命名与传统 CSS 的 `flex-direction` 恰好相反：

- **缺省或 `direction: "column"`（思源默认模式）**：
  - **实际代表左右两栏横向排布**：左侧是占用剩余宽度的 `fn__flex-1`（放置标题与说明文本），右侧是操作控件（`actionElement`）。
  - **强制注入尺寸限制**：思源内核会无差别地为 `actionElement` 添加 `.fn__flex-center` 和 `.fn__size200`（限制宽度为 200px）。
  - **踩坑后果**：如果将整个大面板（如包含多个字段的 AI 配置表单）当作 `actionElement` 传给默认模式，内核会把整个面板当成右侧 200px 小控件，导致左侧标题区占据半边空白，大面板被严重挤压在右半边。

- **`direction: "row"`（思源上下块级模式）**：
  - **实际代表上下纵向堆叠排布**：即标题与说明在上方，操作控件另起一行在下方。
  - **自动注入全宽属性**：思源内核会自动为 `actionElement` 注入 `.fn__block`（`display: block; width: 100% !important;`）。
  - **适用场景**：必须用于复合大表单、多字段面板、配置矩阵等场景。

### 2.2 原生标签推导与响应式折行副作用

1. **容器标签类型推导**：
   - 思源内核在创建行节点时，会检查 `actionElement` 是否包含 `.b3-switch`：若包含则将行容器生成为 `<label class="fn__flex b3-label config-item">`，否则生成为 `<div>`。
   - 当多个开关被打包进一个容器时，可能触发内核意外判定，导致整块区域被视为一个超大 `<label>`。
2. **`.b3-switch` 滑块硬编码机制**：
   - 思源官方 CSS 对 `.b3-switch` 的几何参数是严格按 **`26px × 16px`** 精确硬编码的：
     ```css
     .b3-switch {
       width: 26px;
       height: 16px;
     }
     .b3-switch::after {
       width: 8px;
       height: 8px;
       left: 7px; /* 未开启时小圆点位置 */
     }
     .b3-switch:checked::after {
       width: 12px;
       height: 12px;
       left: 17px; /* 开启时滑块位置 */
     }
     ```
   - **滑块错位根因**：如果外部样式强行将开关尺寸拉伸（例如误设为 `width: 38px; height: 20px;`），由于内核中的 `left: 17px` 是绝对像素定位，开启时的滑块只能停在 17px 处（在 38px 宽度中位于中间靠左），滑块根本无法滑到右边缘，造成严重变形与假死错觉。

## 3. 设置面板最佳实践架构

### 3.1 架构黄金原则

1. **复合大卡片必须声明 `direction: "row"`**，内部字段全宽靠左展开；
2. **常规选项必须逐项调用独立的 `setting.addItem`**，切忌将多个配置选项用一个 `div` 打包塞入；
3. **开关控件必须使用包装容器隔离**，杜绝裸开关被内核追加意外属性；
4. **安装宿主归一化机制（Host Normalizer）**，在 `setting.open()` 时动态清除内核注入的 `.fn__size200` 等副作用。

## 4. 关键实现代码与设计规范

### 4.1 宿主行与面板归一化器（Host Normalizer）

```typescript
/**
 * 复合面板 Normalizer：确保面板 100% 全宽展开，消除 fn__size200 与右偏副作用
 */
export function normalizeSettingPanelHost(panel: HTMLElement | null): void {
  if (!panel || typeof panel.closest !== "function") return

  panel.classList.remove("fn__flex-center", "fn__size200")
  panel.style.width = "100%"
  panel.style.height = "auto"
  panel.style.minHeight = "0"
  panel.style.flex = "none"
  panel.style.alignSelf = "stretch"

  const itemWrap = panel.closest(".config-item, .config__item, .b3-label") || panel.parentElement
  if (itemWrap instanceof HTMLElement) {
    itemWrap.classList.add("slides-settings__host-item")
    itemWrap.style.flexDirection = "column"
    itemWrap.style.alignItems = "stretch"
  }
}

/**
 * 单项设置行 Normalizer：移除开关上的 fn__size200，保证两栏 Grid 对齐
 */
export function normalizeSettingRowHost(control: HTMLElement | null): void {
  if (!control || typeof control.closest !== "function") return

  control.classList.remove("fn__flex-center", "fn__size200", "fn__block")
  const sw = control.matches(".b3-switch") ? control : control.querySelector(".b3-switch")
  if (sw) {
    sw.classList.remove("fn__flex-center", "fn__size200", "fn__block")
  }

  const itemWrap = control.closest(".config-item, .config__item, .b3-label") || control.parentElement
  if (itemWrap instanceof HTMLElement) {
    itemWrap.classList.add("slides-settings__host-row")
    itemWrap.style.alignItems = "center"
  }
}

/**
 * 拦截 setting.open 并执行归一化，支持微任务双重兜底
 */
export function installSettingHostNormalizer(
  setting: any,
  panels: Array<HTMLElement | null>,
  rows: Array<HTMLElement | null>
): void {
  if (!setting || typeof setting.open !== "function") return
  const originalOpen = setting.open.bind(setting)

  const normalizeAll = () => {
    panels.forEach((p) => normalizeSettingPanelHost(p))
    rows.forEach((r) => normalizeSettingRowHost(r))
  }

  setting.open = ((name: string) => {
    originalOpen(name)
    normalizeAll()
    if (typeof setTimeout === "function") {
      setTimeout(() => {
        normalizeAll()
      }, 0)
    }
  })
}
```

### 4.2 开关控件包装器（Switch Wrapper）

使用独立的包装层，同时在 CSS 中严格锁定尺寸为 `26px × 16px`：

```typescript
export function createSwitchWrap(switchEl: HTMLInputElement): HTMLElement {
  const wrap = document.createElement("div")
  wrap.className = "slides-settings__switch-wrap"
  wrap.appendChild(switchEl)
  return wrap
}
```

## 6. 验证检查清单

在完成设置弹窗开发或修改后，请逐一核对以下检查点：
- [ ] **全宽居左核对**：设置窗口中所有标题、表单和提示信息是否均从左侧基线对齐，无孤立空白；
- [ ] **开关滑动验证**：在未开启与开启状态下，开关滑块是否能精准滑到左侧 7px 与右侧 17px，无位置卡顿或尺寸拉伸；
- [ ] **暗色模式校验**：在深色主题（如 Midnight）下核对开关联动背景色与滑块对比度；
- [ ] **眼睛显隐验证**：输入真实 API Key，点击眼睛图标能够无缝在明文与密文之间切换，图标状态同步改变；
- [ ] **接管置灰验证**：当 `siyuan-api-switch` 或外部控制器接管时，相关输入框与眼睛按钮是否同步置灰且不可编辑。
